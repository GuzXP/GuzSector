BAB I: ANALISIS SISTEM BERJALAN

1.1 Deskripsi Proses Bisnis Berjalan (Manual)

Sebelum diterapkannya aplikasi berbasis web pada Warung Nasi Goreng Cak Mol Pulomas, seluruh kegiatan operasional dilakukan secara konvensional (manual):

1.  Pemesanan Menu: Pelanggan datang ke warung, memilih tempat duduk, kemudian pelayan menghampiri meja dengan membawa buku catatan dan pulpen. Pelanggan memesan secara lisan.
2.  Pencatatan Pesanan: Pelayan menulis daftar pesanan, nomor meja, tingkat kepedasan, dan catatan khusus pada secarik kertas nota rangkap.
3.  Penerusan ke Dapur: Lembar nota diserahkan secara fisik ke meja masak Cak Mol. Koki membaca nota antrean kertas yang berisiko basah, terselip, atau hilang.
4.  Pembayaran di Kasir: Pelanggan yang selesai makan mendatangi meja kasir. Kasir mencari kertas nota yang cocok dengan nomor meja, menghitung total bayar menggunakan kalkulator manual, dan menerima uang tunai.
5.  Pencatatan Arsip Menu & Penjualan: Pemilik warung mencatat harga menu dan buku kas penjualan harian menggunakan buku kas fisik yang rentan rusak atau tidak tertib pembukuan.

1.2 Masalah dan Kelemahan Sistem Berjalan

Berdasarkan analisis operasional, kelemahan utama sistem manual meliputi:

-   Keterbatasan Informasi Menu: Pelanggan yang baru pertama kali berkunjung tidak memiliki gambaran visual porsi makanan maupun informasi varian harga terbaru sebelum bertanya langsung.
-   Human Error & Ketidakteraturan Antrean: Pesanan rawan tertukar urutannya saat jam sibuk malam hari, dan kesalahan penulisan level pedas atau catatan tambahan sering terjadi.
-   Ketergantungan Nota Fisik: Nota kertas mudah kotor, sobek, tersiram minyak atau kuah masakan, sehingga kasir kesulitan membaca jumlah item yang dipesan.
-   Perhitungan Lambat: Penghitungan manual memperlambat antrean kasir dan berisiko salah hitung kembalian.
-   Ketiadaan Rekapitulasi Digital: Pemilik kesulitan mendokumentasikan katalog menu yang rapi serta mengevaluasi harga secara terstruktur.

1.3 Solusi Pemecahan Masalah

Dibangunlah aplikasi web terkomputerisasi tahap awal (warungcakmol-copy-2) dengan fokus:

1.  Menyediakan katalog menu digital interaktif yang dapat diakses pelanggan melalui perangkat seluler (user/index.php).
2.  Menyediakan formulir pemesanan online mandiri dengan perhitungan keranjang belanja client-side real-time (user/order.php).
3.  Menerapkan penyimpanan transaksi ACID transaksional melalui database MySQL (user/processorder.php).
4.  Menyediakan antarmuka monitoring pesanan kasir berbasis auto-refresh polling ringan (user/kasir.php & user/pollorders.php).
5.  Membangun modul backend admin terotentikasi untuk manajemen CRUD menu warung beserta ekspor PDF cetak menu (admin/index.php, admin/add.php, admin/edit.php, admin/delete.php, admin/cetakPDF.php).

BAB II: ANALISIS SISTEM USULAN

2.1 Deskripsi Sistem Usulan (Versi Awal)

Sistem usulan versi awal pada repositori warungcakmol-copy-2 mengimplementasikan arsitektur Model-View-Controller sederhana (native procedural PHP) yang terbagi menjadi dua ranah utama:

-   Sisi Pengguna / Pelanggan & Kasir (user/):
    -   Halaman landing page & katalog profil (user/index.php): Menampilkan cerita warung, galeri suasana, ulasan pelanggan, lokasi Google Maps, dan daftar menu terkelompok berdasarkan kategori.
    -   Halaman pemesanan Dine In (user/order.php): Pelanggan memilih menu, mengatur tingkat kepedasan (level 0 s.d. 4) serta catatan khusus, mengelola keranjang pesanan, dan mengirim data via API JSON processorder.php. Menampilkan animasi memasak interaktif dan struk digital sementara.
    -   Halaman kasir monitor (user/kasir.php): Menampilkan kartu antrean pesanan berstatus Pending, didukung mekanisme background polling interval 8 detik ke pollorders.php untuk memicu auto-reload saat ada pesanan baru, serta tombol "Tandai Selesai" untuk memperbarui status pesanan menjadi Selesai.
-   Sisi Administrator (admin/):
    -   Otentikasi login dengan bcrypt hashing dan cookie remember-me SHA-256 (admin/login.php, admin/registrasi.php, admin/logout.php).
    -   Halaman manajemen data menu terpusat (admin/index.php): Menampilkan tabel menu, pencarian langsung keyword (nama, harga, kategori), tautan cetak PDF, tambah, ubah, dan hapus.
    -   Manipulasi data menu (add.php, edit.php, delete.php, fungsi.php): Upload gambar dengan validasi ekstensi/ukuran file dan fungsi unlink otomatis saat penghapusan/penggantian berkas.
    -   Pencetakan laporan menu (admin/cetakPDF.php): Menggunakan pustaka vendor mPDF dengan orientasi landscape.

2.2 Dekomposisi Fungsional Sistem

Struktur dekomposisi sistem versi awal dipecah menjadi sub-sistem berikut:

1.  Sub-Sistem Profil & Katalog: Penayangan profil warung, statistik penilaian, ulasan, jam operasional, peta lokasi, dan tab filter kategori menu dinamis.
2.  Sub-Sistem Pemesanan Mandiri: Pemilihan item, seleksi level kepedasan, penulisan catatan kustom, kalkulator keranjang lokal, validasi pesanan di server, perekaman ACID transaksi header-detail.
3.  Sub-Sistem Monitoring Kasir: Pemantauan antrean pending real-time berbasis AJAX polling, inspeksi snapshot menu pesanan, dan penutupan transaksi pesanan.
4.  Sub-Sistem Manajemen Menu Admin: Otentikasi sesi administrator, pencarian menu, penambahan menu baru dengan upload foto, pembaruan atribut menu, penghapusan menu, dan cetak katalog dokumen PDF.

2.3 Perbandingan Sistem Manual vs Sistem Usulan

| Parameter | Sistem Manual Berjalan | Sistem Usulan Versi Awal (warungcakmol-copy-2) |
| --- | --- | --- |
| Penyajian Menu | Buku menu fisik / lisan, tidak ada foto | Katalog web interaktif + foto resolusi tajam (user/index.php) |
| Input Pesanan | Kertas nota manual oleh pelayan | Input digital mandiri oleh pelanggan (user/order.php) |
| Penyimpanan Pesanan | Kertas terselip / tercecer | Database relasional MySQL tabel pesanan dan detailpesanan |
| Integritas Data Transaksi | Sangat rentan hilang | Database ACID Transaction (mysqlibegintransaction) |
| Monitoring Antrean Kasir | Mengurutkan tumpukan kertas nota | Tampilan grid kartu kasir monitor + auto-polling 8 detik |
| Penyelesaian Order | Coret nota manual | Klik tombol "Tandai Selesai" (Update query SQL) |
| Kelola Data Menu | Catat di buku fisik / papan tulis | Dashboard CRUD Admin terintegrasi + Pencarian data |
| Cetak Dokumen Menu | Ketik ulang / tulis tangan | Export instan ke file PDF via library mPDF |

BAB VII: KESIMPULAN DAN EVALUASI VERSI AWAL

Berdasarkan analisis menyeluruh terhadap codebase versi awal (warungcakmol-copy-2), sistem telah berhasil menyelesaikan permasalahan operasional dasar yaitu:

1.  Digitalisasi buku menu warung Cak Mol dengan galeri visual yang menarik dan interaktif.
2.  Penanganan transaksi pemesanan secara transaksional ACID sehingga data pesanan pelanggan tidak tercecer.
3.  Monitoring antrean pesanan kasir secara semi-realtime dengan auto-refresh polling.
4.  Pengelolaan master data menu warung terproteksi otentikasi admin dengan dukungan pencetakan dokumen PDF.

Kelemahan Arsitektur & Kebutuhan Pengembangan Selanjutnya:

Meskipun telah berjalan dengan baik, evaluasi analitis menemukan sejumlah keterbatasan mendasar pada versi awal ini yang menjadi landasan pembaruan menuju versi terbaru:

1.  Keamanan Kasir: Halaman kasir (user/kasir.php) belum diproteksi oleh otentikasi login, sehingga siapa pun yang mengetahui URL dapat menandai pesanan selesai.
2.  Ketiadaan Modul Dapur (KDS): Koki di dapur belum memiliki monitor display pesanan tersendiri untuk melihat antrean masakan dan memperbarui progres memasak (Menunggu -> Dimasak -> Siap).
3.  Keterbatasan Opsi Pemesanan: Sistem hanya mendukung Dine In dengan nomor meja statis hardcoded, belum mendukung pemesanan Bawa Pulang (Takeaway) maupun integrasi kode QR meja.
4.  Pembayaran Terbatas: Kasir belum memiliki fasilitas kalkulator kembalian uang tunai, belum ada integrasi QRIS, dan belum dapat mencetak struk kasir printer thermal fisik.
5.  Ketiadaan Manajemen Finansial: Administrator belum dapat memantau grafik laba rugi, pencatatan uang masuk dan uang keluar harian, serta pengaturan profil dinamis warung.

BAB I: ANALISIS SISTEM BERJALAN

1.1 Deskripsi Proses Bisnis Berjalan (Sistem Versi Sebelumnya)

Pada sistem versi sebelumnya (warungcakmol-copy-2), proses bisnis telah terdigitalisasi secara bertahap namun masih memiliki keterbatasan integrasi antarlini:

1.  Pemesanan Pelanggan: Pelanggan memesan secara mandiri melalui web, namun sistem mengasumsikan meja secara statis (hardcoded meja 1) tanpa fleksibilitas pemilihan meja maupun dukungan pesanan bawa pulang (Takeaway).
2.  Ketiadaan Komunikasi Dapur: Setelah pelanggan menekan tombol konfirmasi pesanan, data langsung berstatus Pending dan hanya dipantau oleh kasir. Dapur tidak memiliki layar tampilan terpisah, sehingga koki masih harus bertanya secara lisan ke kasir mengenai apa yang harus dimasak.
3.  Pembayaran Kasir: Kasir melihat antrean tanpa proteksi login akun. Penyelesaian transaksi hanya mengklik satu tombol tanpa opsi pencatatan metode bayar (tunai/nontunai), tanpa kalkulator kembalian, dan tanpa bukti cetak struk kasir fisik.
4.  Administrasi Terbatas: Sisi admin hanya difungsikan untuk CRUD menu dan cetak PDF menu. Arus kas (uang masuk dan keluar), grafik omzet mingguan, barang terlaris, dan data profil warung belum tercatat secara digital.

1.2 Identifikasi Kelemahan dan Keterbatasan Arsitektur Sebelumnya

Evaluasi komprehensif terhadap codebase lama menemukan poin-poin kritis berikut:

-   Celah Keamanan (Vulnerability):
    -   File user/kasir.php tidak memiliki sesi verifikasi hak akses, membuka risiko unauthorized access dari pelanggan yang membuka URL kasir.
    -   Form transaksi belum memiliki proteksi token CSRF (Cross-Site Request Forgery).
    -   Skrip koneksi database tersebar terpisah-pisah di berbagai subdirektori (admin/koneksi.php, user/koneksi.php) tanpa konfigurasi terpusat.
-   Ketiadaan Kitchen Display System (KDS):
    -   Antrean pesanan menumpuk di kasir tanpa pemisahan alur kerja dapur (tahap Menunggu -> Dimasak -> Siap Saji).
-   Skema Basis Data Minimalis:
    -   Tabel pesanan belum mencatat nama pemesan, tipe pesanan (Dine In vs Takeaway), metode pembayaran, dan waktu selesai transaksi.
    -   Relasi meja kaku, di mana pemesanan takeaway tidak dimungkinkan karena kolom idmeja wajib terisi (NOT NULL).
    -   Belum ada tabel kategori, pengaturan, uangmasuk, dan uangkeluar.

1.3 Kebutuhan Pembaruan Sistem (Urgency of Enhancement)

Berdasarkan evaluasi di atas, pembaruan menyeluruh pada codebase warungcakmol-copy menjadi kebutuhan mendesak melalui:

1.  Restrukturisasi arsitektur direktori dengan membuat modul pustaka inti includes/ (koneksi.php, auth.php, helpers.php).
2.  Perluasan basis data dari 4 tabel menjadi 8 tabel relasional yang dinamis dan terstruktur.
3.  Pembangunan modul khusus dapur kitchen/ (Kitchen Display System) berbasis real-time polling 5 detik dengan audio synthesizer notification.
4.  Peningkatan keamanan kasir (confirmkasirlogin()), modal pembayaran dwimetode (Cash & QRIS), kalkulator uang kembalian cepat, dan cetak struk ramah thermal printer 58mm/80mm (user/cetakstruk.php).
5.  Transformasi dashboard admin menjadi Single Page Dashboard komprehensif yang memuat metrik omzet, grafik 7 hari, rangkuman laba/rugi, pencatatan kas keluar/masuk, dan pengelolaan profil warung.

BAB II: ANALISIS SISTEM USULAN

2.1 Deskripsi Sistem Usulan (Versi Terbaru)

Sistem usulan pada codebase terbaru (warungcakmol-copy) merupakan sistem Point of Sale (POS) dan Kitchen Display System (KDS) terintegrasi penuh yang menghubungkan 4 aktor kunci: Pelanggan, Koki Dapur, Kasir, dan Admin/Pemilik.

Sistem ini memiliki keunggulan arsitektural:

1.  Modul Pengguna Mandiri (user/):
    -   index.php: Landing page interaktif dengan data kategori dinamis dari tabel kategori.
    -   order.php: Pemesanan Dine In dengan dukungan pemindaian QR Code meja (?meja=kode-qr) atau pemilihan dropdown meja interaktif, penulisan nama pelanggan opsional, dan persistensi keranjang via localStorage.
    -   takeaway.php: Pemesanan Bawa Pulang khusus dengan input nama pemesan wajib dan pengalokasian idmeja = NULL.
    -   processorder.php: API transaksi transaksional (ACID) dengan sanitasi input berlapis, validasi harga server-side, dan pencatatan awal status dapur Menunggu.
    -   kasir.php: Monitor kasir terproteksi otentikasi login, deteksi badge status dapur dengan animasi pulse-green jika makanan siap saji, modal popup kalkulator pembayaran (Cash/QRIS), dan pelepasan status meja otomatis kembali menjadi Kosong.
    -   cetakstruk.php: Generator struk belanja thermal printer otomatis trigger window print.
2.  Modul Kitchen Display System (kitchen/):
    -   index.php: Antarmuka layar dapur 2 kolom (Menunggu dan Sedang Dimasak), filter kategori cepat, timer durasi pesanan dinamis, dan bunyi alert lonceng audio synthesizer saat pesanan baru masuk.
    -   pollkitchen.php: API penyaji daftar menu pesanan pending berbasis polling 5 detik.
    -   updatestatus.php: API pengubah status masakan (Menunggu -> Dimasak -> Siap).
3.  Modul Administrator & Finansial (admin/):
    -   index.php: Dashboard analitik (omzet total, pesanan selesai, laba bersih, grafik omzet mingguan Chart.js, menu terlaris, transaksi terbaru), tab Manajemen Menu, tab Keuangan (arus kas masuk, kas operasional keluar, net profit/loss), dan tab Pengaturan Warung.
    -   cetakLaporan.php: Generator laporan PDF ikhtisar laba/rugi dan rincian transaksi via mPDF.
    -   cetakPDF.php: Generator katalog menu landscape via mPDF.
4.  Pustaka Inti Terpusat (includes/):
    -   koneksi.php: Koneksi MySQLi terpusat dengan charset UTF-8.
    -   auth.php: Proteksi sesi bertingkat (confirmadminlogin(), confirmkasirlogin(), initusersession()) dengan regenerasi session ID periodik.
    -   helpers.php: Generator & validator token CSRF, fungsi sanitasi anti-XSS htmlspecialchars(), dan pemformat mata uang Rupiah.

BAB VII: KESIMPULAN DAN REKOMENDASI PENGEMBANGAN

7.1 Kesimpulan

Pembaruan menyeluruh pada codebase warungcakmol-copy telah berhasil mentransformasi aplikasi warung nasi goreng sederhana menjadi sistem operasional terintegrasi kelas enterprise mini yang memenuhi kaidah Rekayasa Perangkat Lunak:

1.  Peningkatan Keamanan Terstruktur: Penerapan token CSRF, proteksi akses kasir berbasis otentikasi peran, regenerasi session ID periodik, dan sentralisasi helper sanitasi SQL/XSS mencegah eksploitasi data secara efektif.
2.  Sinkronisasi Multi-Lini Terpadu: Integrasi antara modul Pelanggan (QR Code Dine In & Takeaway), modul Dapur (Kitchen Display System dengan Web Audio alert), dan modul Kasir (Modal pembayaran dwimetode Cash/QRIS & auto-release status meja) meniadakan ketergantungan pada nota kertas dan komunikasi lisan yang rawan salah.
3.  Pemberdayaan Finansial & Analitik Bisnis: Pemilik warung kini memiliki visibilitas total terhadap grafik omzet harian, 5 menu terlaris, rekapitulasi laba/rugi, pencatatan kas operasional, dan fasilitas ekspor PDF resmi.

7.2 Rekomendasi Pengembangan Mendatang (Future Roadmap)

Untuk pengembangan tahap selanjutnya, sistem dapat diperkaya dengan:

1.  Integrasi Payment Gateway Otomatis: Menghubungkan QRIS dengan callback Webhook pihak ketiga (seperti Midtrans atau Xendit) untuk verifikasi pembayaran QRIS otomatis tanpa cek manual.
2.  WebSockets Push Notification: Menggantikan mekanisme AJAX Polling interval dengan protokol WebSocket (misal: Socket.io / Ratchet PHP) guna mereduksi latensi dan meningkatkan efisiensi server.
3.  Penyusutan Bahan Baku Otomatis (Inventory Stock Deduction): Mengaitkan menu yang terjual dengan pengurangan kuantitas stok bahan mentah (beras, telur, minyak) secara otomatis di gudang.
